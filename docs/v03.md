# Structural v0.3

v0.3 adds operational reliability without changing the structural authority model.

## External execution refs

Optional SKLT `execution` refs integrate with the current Toolkit boundary:

```text
execution:
    provider: rust_makepad_toolkit
    kind: container
    id: docker-linux-level0
    purpose: ai-ui-test
```

`docker-linux-level0` is an external execution reference, not a bundled environment or a promise that it is available on the reader's machine. Dungeon System stores no image, mount, limit, permission or lifecycle configuration. When using an authorized external Toolkit checkout, its entry point is `<TOOLKIT_ROOT>/docs/INDEX.md`.

Object index serializes refs as typed objects:

```json
{"type": "container", "provider": "rust_makepad_toolkit", "id": "docker-linux-level0"}
```

Malformed refs are errors. If the current external catalog cannot be resolved, the ref is reported separately as an unresolved warning. A known but absent Toolkit container key is an error. Existing SKLT without `execution` remains backward compatible.

## Entry commands

```text
python tools/project-structure.py status
python tools/project-structure.py scan --json
python tools/project-structure.py validate --json
python tools/project-structure.py index
python tools/project-structure.py inspect renderer.settings --json
```

Recommended flow:

```text
status → docs/project.md → docs/map.md → inspect <object_id>
      → SKLT → GLIF/source refs
      → Toolkit docs/INDEX.md and specialized guide, if needed
      → validate → exp / index → snapshot-diff / Cronica
```

Schema version `1` is supported for the manifest, SKLT, GLIF, library, snapshot and object-index formats. Missing schema fields in existing files are interpreted as legacy v1.
